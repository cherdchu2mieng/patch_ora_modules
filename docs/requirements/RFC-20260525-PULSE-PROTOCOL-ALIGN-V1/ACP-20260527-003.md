## Objective / วัตถุประสงค์

เพื่อตรวจสอบความเสถียรและการทำงานร่วมกันของทุก Change Request (CR-000 ถึง CR-007.v1) ตามข้อกำหนดสเปกอย่างละเอียดเชิงประจักษ์

## Scenario 0: Foundational Setup & Identity / การตั้งค่าพื้นฐานและตัวตน
*Tests integration of CR-000 (init).*

1.  **System Initialization (การเริ่มระบบ)**:
    *   **Action**: Delete (or backup) your local `pulse.config.json`. Run `pulse init`.
    *   **[TH]**: ลบหรือสำรองไฟล์ `pulse.config.json` เดิม แล้วรันคำสั่ง `pulse init`
    *   **Expected**: The command creates a new `pulse.config.json` with correct mapping.
    *   **[TH]**: ระบบต้องสร้างไฟล์คอนฟิกใหม่ที่มีการแมปค่า Org และ Repository ที่ถูกต้อง
2.  **Identity Resolution (การตรวจสอบตัวตน)**:
    *   **Action**: Run `pulse board`.
    *   **[TH]**: รันคำสั่ง `pulse board`
    *   **Expected**: Command correctly identifies your current Oracle name based on the workspace path.
    *   **[TH]**: คำสั่งต้องระบุชื่อ Oracle ของคุณได้ถูกต้องโดยอ้างอิงจากชื่อโฟลเดอร์ที่ทำงานอยู่

## Scenario 1: The Core Lifecycle / วงจรชีวิตงานหลัก (ITB -> AIB -> ITB)
*Tests integration of CR-004 (chb), CR-003 (start), and CR-001 (add).*

1.  **Ingress (การดึงงานเข้า)**:
    *   **Action**: Identify a task assigned to you on ITB. Run `pulse chb <#> --Delegated`.
    *   **[TH]**: เลือกงานที่ได้รับมอบหมายบนบอร์ดทีม (ITB) แล้วรัน `pulse chb <#> --Delegated`
    *   **Expected**: Task on ITB changes to `In Progress` with Anchor. Task on AIB is created with Status `Delegated`.
    *   **[TH]**: งานบน ITB ต้องเปลี่ยนเป็น `In Progress` พร้อมสร้าง Anchor เชื่อมโยง และงานต้องไปปรากฏบนบอร์ดส่วนตัว (AIB) ด้วยสถานะ `Delegated`
2.  **Start Execution (การเริ่มลงมือทำ)**:
    *   **Action**: Run `pulse start <#>` on the AIB task.
    *   **[TH]**: รัน `pulse start <#>` บนงานในบอร์ดส่วนตัว
    *   **Expected**: Task status changes to `In Progress`. Start Date is recorded.
    *   **[TH]**: สถานะงานต้องเปลี่ยนเป็น `In Progress` และมีการบันทึกวันที่เริ่มงานลงในระบบ
3.  **Return (การส่งคืนงาน)**:
    *   **Action**: Run `pulse chb <#> --Returned` on AIB.
    *   **[TH]**: เมื่อเสร็จงาน ให้รัน `pulse chb <#> --Returned` บนบอร์ดส่วนตัว
    *   **Expected**: Task on AIB changes to `Returned`. Task on ITB automatically changes to `Done`.
    *   **[TH]**: งานบนบอร์ดส่วนตัวต้องเปลี่ยนเป็น `Returned` และงานต้นทางบนบอร์ดทีมต้องเปลี่ยนเป็น `Done` โดยอัตโนมัติ

## Scenario 2: Orchestrator Broadcast / การประกาศข่าวสารโดย Orchestrator
*Tests integration of CR-006.v1 (blog).*

1.  **Broadcast (การประกาศ)**:
    *   **Action**: Run `pulse blog <markdown_file>`.
    *   **[TH]**: รันคำสั่ง `pulse blog` ตามด้วยชื่อไฟล์ Markdown
    *   **Expected**: Post is published to `itinfosv/pulse-oracle` Discussions. Frontmatter is updated with the URL.
    *   **[TH]**: ข้อมูลต้องถูกโพสต์ไปยัง GitHub Discussions ของทีม และไฟล์ต้นทางต้องถูกอัปเดต URL ในส่วน Frontmatter

## Scenario 3: Authority and Security Gates / ด่านกักกันสิทธิ์และความปลอดภัย
*Tests integration of CR-007.v1 (close).*

1.  **Identity Guard (การป้องกันการสวมรอย)**:
    *   **Action**: Attempt to run `pulse close <#>` on a task assigned to a *different* Oracle.
    *   **[TH]**: พยายามรัน `pulse close` ในงานที่ **ไม่ใช่ของคุณ**
    *   **Expected**: Command is blocked with `❌ Authority Error`.
    *   **[TH]**: คำสั่งต้องถูกบล็อกและแจ้งเตือนข้อผิดพลาดเรื่องสิทธิ์ (Authority Error)
2.  **Context-Aware Closure (การปิดงานตามบริบท)**:
    *   **Action**: Run `pulse close <#>` on an eligible task in ITB context.
    *   **[TH]**: รันคำสั่ง `pulse close` ในงานบนบอร์ดทีม (ITB)
    *   **Expected**: Task status changes to `Closed`.
    *   **[TH]**: สถานะงานต้องเปลี่ยนเป็น `Closed` อย่างถูกต้องตามบริบทของบอร์ดบริหารจัดการ
